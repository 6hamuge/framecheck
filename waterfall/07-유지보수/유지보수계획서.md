# 유지보수계획서

| 항목 | 내용 |
| --- | --- |
| 프로젝트·릴리스 | FrameCheck · 학회 실습용 MVP |
| 문서 ID·작성일 | MTP-FRAMECHECK-v0.1 · 2026-11-24 |
| 상태 | Phase 7 계획 초안 · 운영 인수 대기 |
| 운영 기준선 | G6에서 확인한 배포 버전, 운영 가이드와 복구 대상. 현재 미확정. |

## 1. 유지보수 유형

| 유형 | FrameCheck 적용 예 | 확인 방법 |
| --- | --- | --- |
| 수정 | JPEG·PNG 오류, 시점·영역 불일치, 저장 버튼의 잘못된 상태 | 재현 TC 및 영향받는 인접 흐름 재검증 |
| 적응 | 브라우저 코덱 지원 변화, 호스트 변경, 모바일 다운로드 동작 변화 | DEC-002의 지원 매트릭스와 전체 흐름을 다시 확인 |
| 개선 | 입력 제한 안내와 접근성, 비교 확인 동선 개선 | UX 검토 지적과 관련 AC를 기준으로 검증 |
| 예방 | 임시 URL 수명 점검, 샘플 권리와 이전 배포 버전 점검 | 로컬 처리·수명과 복구 점검 기록 |

딥페이크 판정, 전체 영상 재인코딩, 클라우드 저장은 서비스 기획서의 후속 범위로 관리한다. 이 범위가 바뀌면 기능 영향과 데이터 처리 경계를 기획 단계에서 다시 검토한다.

## 2. 변경 요청과 릴리스 절차

1. 요청에 버전·환경·재현 단계, 영향받는 동작과 증빙을 남긴다. 사용자 영상 내용과 프레임은 권리 확인된 재현 자료로 대체한다.
2. 변경 이유와 영향받는 MVP·정책·FR/NFR·AC를 확인하고, 프로젝트 책임자가 반영 범위와 릴리스를 결정한다.
3. 개발 담당이 수정하고 QA가 재현 케이스와 회귀를 확인한다. 영상·프레임·상태 처리를 바꾸면 샘플·로컬 전체 흐름, 최신 결과 저장, 브라우저 데이터 경계를 함께 점검한다.
4. 승인 후보를 배포하고 운영 주소에서 확인한다. 버전, 변경 요청, 테스트 증빙, 복구 대상과 관련 문서를 연결한다.

## 3. 대응 우선순위와 점검 시점

| 우선순위 | 예 | 목표 동작 |
| --- | --- | --- |
| 긴급 | 사용자 미디어 외부 전송, 전체 비교·저장 실패, 잘못된 PNG 제공 | 발견 즉시 책임자·배포 담당에게 전달하고 영향 버전의 중단·복구 여부 판단 |
| 높음 | 지원 환경에서 반복되는 영상 읽기·변환 실패 | 다음 시연 전 재현·범위 확인 및 수정 또는 우회 경로 안내 |
| 일반 | 안내 문구, 비차단 레이아웃, 개선 요청 | 다음 유지보수 검토에서 변경 범위와 회귀 검증 결정 |

위 목표는 학회 실습 운영 우선순위다. 응답·복구 시간의 계약 수치는 정해지지 않았다. 시연 전, 지원 브라우저·샘플 변경 후, 장애 복구 후 점검한다. 담당자와 실제 운영 일정은 G6 이후 운영 인수 기록에 연결한다.

## 4. 인수·기술 부채

| 인수 대상 | 필요한 기록 | 현재 상태 |
| --- | --- | --- |
| 정적 버전·운영 환경 | 운영 URL, 해시 또는 배포 ID, 복구 후보와 실행 권한 | 미확정 |
| 브라우저 호환성·샘플 | 대상 기기·OS·브라우저·코덱, 샘플 권리와 대체 클립 위치 | DEC-001·DEC-002 확인 대기 |
| 장애·변경 기록 | 접수 위치, 우선순위 분류 담당, 변경·검증 증빙 | 인수 전 |
| 점검 자동화 후보 | 소규모 회귀에서 반복 비용이 큰 항목을 인수 후 선정 | 평가 대기 |
