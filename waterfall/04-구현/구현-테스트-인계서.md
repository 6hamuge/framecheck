# 구현·테스트 인계서

## 1. 구현 범위

| 요구사항 | 수용 기준 | 계획 위치 | 현재 확인 결과 |
| --- | --- | --- | --- |
| FR-001, FR-002 | AC-001, AC-002 · 로컬 입력과 샘플 열기 | MOD-001, MOD-002 · 영상 선택·검증, 디코딩, 샘플 자산 | 후보 확인 · 로컬과 샘플 확인 |
| FR-003 | AC-003 · 동일 시점 갱신과 기존 영역 초기화 | MOD-001, MOD-002 · 타임라인과 프레임 캡처 | 후보 확인 |
| FR-004, FR-005 | AC-004, AC-005 · 관심 영역과 실제 JPEG 변환 | MOD-003 · 픽셀 좌표 계산, 축소, JPEG 인코딩 및 크롭 | 후보 확인 |
| FR-006 | AC-006 · 최신 비교 결과 PNG 저장 | MOD-001, MOD-004 · 버튼 활성 조건, PNG 합성과 다운로드 | 후보 확인 |
| FR-007 | AC-007 · 최신 요청과 오류 복구 | MOD-001~MOD-004 · 갱신 상태, 다시 시도, 이전 결과 폐기 | 후보 확인 |
| NFR-001, NFR-002 | AC-008, AC-009 · 로컬 처리와 임시 데이터 정리 | MOD-002~MOD-004 · 브라우저 메모리, 객체 URL, 다운로드 | 후보 확인 |
| NFR-003, NFR-004 | AC-010, AC-011 · 모바일·데스크톱 및 접근성 | MOD-001~MOD-003 · 화면 배치, 브라우저 디코딩, 키보드 조작 | 후보 확인 · 실제 모바일과 스크린리더 대기 |

계획 위치의 MOD-ID는 상세설계서 기준이다. RTM에 후보와 구현 파일 및 TC-ID를 연결했다. 초안 기준선 대비 설계가 바뀐 경우 영향받는 FR·NFR·AC, 변경 이유와 승인 기록을 함께 남긴다.

## 2. 빌드와 테스트 환경

| 항목 | 인계 기준 |
| --- | --- |
| 실행 방식 | 빌드 단계가 없는 HTML·CSS·JavaScript 정적 앱. 후보에는 `framecheck/dist/index.html`, `styles.css`, `app.js` 및 같은 출처에서 읽는 샘플·포스터를 포함한다. |
| 로컬 실행 | 후보를 체크아웃한 작업 폴더 루트에서 아래 명령으로 실행한다. QA 재현 기록에 후보 SHA, 운영체제, Python 및 브라우저 버전을 남긴다. |
| QA 환경·접근 | 로컬 루프백 주소를 기본으로 사용한다. 공유 미리보기가 필요하면 후보 SHA와 연결된 HTTPS 주소, 접근 방법과 담당자를 기록한다. 대상 모바일·데스크톱 브라우저와 코덱 조합은 DEC-002에서 확정한다. |
| 환경 설정·외부 연동 | 서버 API, DB, 마이그레이션 및 인증 자격 증명은 해당 없음. 영상 디코딩과 이미지 생성은 대상 브라우저에서 수행한다. |
| 초기화·테스트 자료 | 새로고침으로 페이지 작업을 초기화한다. 출처·배포·시연 권리가 확인된 샘플·포스터(DEC-001)와 아래 픽스처를 후보에 맞춰 준비한다. |

```sh
node --check framecheck/dist/app.js
python3 -m http.server 8000 --bind 127.0.0.1 --directory framecheck/dist
```

첫 명령은 JavaScript 문법 검사다. 두 번째 명령으로 실행한 뒤 `http://127.0.0.1:8000/`에서 화면을 확인한다. 브라우저 실행이 가능한 후보에 두 명령을 적용하고 결과를 기록한다.

## 3. 구현 점검 결과와 QA 우선 시나리오

| 점검 | 확인 결과 | 증빙 또는 다음 기록 |
| --- | --- | --- |
| 로컬 소스·후보 식별 | 확인 · 작업 폴더의 모든 배포 파일이 후보에 포함된 내용과 일치 | 후보 커밋으로 검증 |
| 빌드 및 문법 검사 | 별도 빌드 단계 해당 없음 · JavaScript 문법 검사 통과 | 후보 파일에 `node --check` 실행 |
| 코드 리뷰 및 단위 검증 | 미실행 | 후보 PR 또는 검토 기록, 영역·픽셀 계산 경계 점검 결과 연결 |
| 브라우저 핵심 흐름과 실패 경로 | 13개 통과, 2개 부분 검증 | [테스트결과보고서](../05-테스트/테스트결과보고서.md) |
| 테스트 케이스 매핑 | TC 15개 연결 | SRS AC 및 후보 결과를 RTM에 연결 |

아래는 SRS의 수용 기준을 테스트케이스로 옮기기 위한 검증 후보다.

| 수용 기준 | 준비물과 우선 확인 |
| --- | --- |
| AC-001, AC-002 | 재생 가능한 MP4·WebM과 권리 확인 샘플. 정확히 50,000,000바이트·30초인 경우와 각각의 초과, 미지원 형식·손상 파일을 분리해 검증한다. 오류 후 다른 파일과 샘플로 다시 시작한다. |
| AC-003~AC-005 | 시점마다 장면이 구분되고 세부가 보이는 영상. 시점을 바꾸면 두 카드가 동기화되고 이전 영역이 지워진다. 드래그와 좌표 입력을 대조하고 50% 축소, 홀수 크기의 가장자리, JPEG 품질만 바꿀 때의 크기 유지 및 실제 JPEG 결과를 확인한다. |
| AC-006, AC-007 | 영역 미선택·갱신 중 저장 상태를 확인한다. 연속 탐색·설정 변경과 처리 순서가 뒤바뀌는 경우 최신 결과만 표시·저장되는지 확인한다. 변환·PNG 생성 실패 후 재시도하고, PNG의 두 이미지와 시점·설정·픽셀 수를 화면과 대조한다. |
| AC-008, AC-009 | 네트워크·브라우저 저장소를 확인해 로컬 미디어의 서버 전송과 영구 앱 저장이 0건인지 확인한다. 영상 교체 시 불필요한 객체 URL 해제, 새로고침 후 초기화와 이전 다운로드 파일 유지를 확인한다. |
| AC-010, AC-011 | 승인된 데스크톱·모바일과 MP4·WebM 조합, 767px·768px 화면을 확인한다. 키보드로 열기부터 저장까지 수행하고 포커스·라벨·상태 읽기와 주요 조작부의 44px 터치 영역을 점검한다. |

## 4. 인계 전 해결할 항목

| 항목 | 영향 | 담당 역할·확인 시점 |
| --- | --- | --- |
| 후보와 실행 증빙 확인, 공식 코드 검토 및 QA 인수 기록 확보 | 전체 요구사항의 QA 재현과 G4 후보 식별 | 개발 담당 · G4 검토 전 |
| 샘플과 기본 테스트 픽스처 확인 · 실제 기기 환경에서 재검증 | AC-001, AC-002, AC-005, AC-010 | 콘텐츠 담당 및 QA · 후보 인계 전 |
| 대상 브라우저·기기 및 코덱 조합 확정 | AC-001, AC-007, AC-010, AC-011 | 개발·QA · G4 검토 전 |
| 압축 설정 초기값과 픽셀 대응 규칙의 상위 설계 승인 확인 | AC-004~AC-006 · REQ-DEC-001, REQ-DEC-002 | 기획·설계 담당 · 구현 기준선 확정 시 |
| FrameCheck 테스트 진입 조건과 TC-ID 매핑 확인 | 전체 AC · 로컬 후보 추적을 공식 인계에서 확인 | QA · G4 검토 전 |

압축 기본값은 상세설계서의 해상도 100%, JPEG 품질 75 검토안을 사용한다. 축소 영역에는 원본 픽셀 경계의 시작 내림·끝 올림 규칙을 검토안으로 적용한다. 후보 인계 시 승인값과 실제 구현값을 비교한다.

## 6. 얼굴 분석 확장 인계

| 항목 | 기록 |
| --- | --- |
| 구현 후보 위치 | 작업 폴더 `framecheck/dist/`의 HTML·CSS, app.js 및 신규 face-analysis.js |
| 검증 범위 | FR-008~010 / AC-012~014. 샘플과 얼굴 없는 로컬 MP4, 자동 선택, 설정·시점 변경, 변환본 미검출과 기본 PNG 경로를 확인한다. |
| 실행 재현 | 기존 로컬 HTTP 명령 사용. 최초 분석에는 jsDelivr 및 Google Storage 정적 자산에 대한 연결이 필요하다. |
| 다음 인계 조건 | 로컬 모델 다운로드 실패와 네트워크 계측 결과는 결과보고서에 기록했다. 확장 후보 릴리스 식별자와 실제 기기·스크린리더 결과를 추가한다. |

이 문서 본문의 기존 후보 SHA는 AI 확장 이전의 검증 기록이다.
