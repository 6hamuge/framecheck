## 1. API 적용 범위

| 대상 | 판정 | 근거 |
| --- | --- | --- |
| 애플리케이션 HTTP API, 외부 서비스 API | 해당 없음 · 엔드포인트 0개 | 파일 입력, 프레임 비교, PNG 저장은 브라우저에서 완료한다. NFR-001 및 BP-LOCAL-001을 적용한다. |
| 인증, 인가, JSON 공통 규격, API 버전, 호출 제한, OpenAPI | 해당 없음 | 이번 실습의 호출 대상은 브라우저 기능과 정적 호스트다. |
| 정적 자산 요청 | 적용 | 진입 문서, CSS, JavaScript, 샘플 영상과 정지 프레임을 같은 출처에서 읽는다. 샘플 영상은 호스트와 브라우저가 제공하는 일반 정적 미디어 전송을 사용한다. |
| 브라우저 인터페이스 | 적용 | 아래 입력·출력 규격을 화면, 영상 처리, 결과 저장에서 공통으로 사용한다. |

## 2. 브라우저 인터페이스

아래 매핑은 브라우저 기능과 작업 단위의 계약이다. 구체적인 함수 이름과 파일 분리는 상세 설계에서 정한다.

| ID | 작업 · 인터페이스 | 입력 | 성공 결과 | 요구사항 |
| --- | --- | --- | --- | --- |
| IF-001 | 로컬 영상 또는 샘플 열기 · 파일 입력, 객체 URL, `HTMLVideoElement` | 로컬 `File` 또는 같은 출처 샘플 경로 | 유효한 영상 길이·프레임 크기 및 첫 프레임 | FR-001, FR-002, NFR-001, NFR-002 |
| IF-002 | 영상 시점 캡처 · `currentTime`, 미디어 준비·탐색 완료 이벤트, Canvas 2D | 활성 영상, 목표 시점 | 같은 비교에 사용할 원본 캡처와 확인된 시점 | FR-003, FR-007 |
| IF-003 | 영역 좌표 및 JPEG 변환 · 포인터·수치 입력, Canvas 2D, `toBlob` | 현재 원본 캡처, 원본 픽셀 영역 또는 미선택, 해상도 비율, JPEG 품질 | 디코딩된 JPEG, 두 프레임의 크기, 선택 시 두 크롭의 픽셀 위치·크기 | FR-004, FR-005, FR-007 |
| IF-004 | PNG 생성 및 다운로드 · Canvas 2D, `toBlob`, 객체 URL과 다운로드 링크 | 현재 비교 스냅샷 및 저장 요청 | 한 장의 PNG 다운로드, 화면 메타데이터와 대응하는 표기 | FR-006, FR-007, NFR-001, NFR-002 |

- 파일 선택은 로컬 `File`을 얻는 동작이다. 앱은 이 파일을 영상 요소에 연결하고, 소스를 분리한 뒤 더 이상 필요 없는 객체 URL을 해제한다. 임시 JPEG·PNG URL도 사용을 마친 뒤 해제한다. [W3C File API · Blob URL](https://w3c.github.io/FileAPI/#url)
- JPEG 변환은 `image/jpeg`와 품질 값을 사용한다. PNG 저장은 `image/png`로 요청한다. 각 결과의 형식을 확인하고, 인코딩 결과가 비어 있거나 요청한 형식과 일치하지 않으면 실패로 처리한다. [WHATWG Canvas 이미지 직렬화](https://html.spec.whatwg.org/multipage/canvas.html#serialising-bitmaps-to-a-file)

## 3. 입력 경계와 오류 전달

| 실패 구분 | 판정 · UI 결과 |
| --- | --- |
| 형식 · 용량 | 로컬 입력의 MP4·WebM 형식과 50,000,000바이트 상한을 확인한다. 제한 위반 유형을 파일 열기 버튼 근처에 전달한다. |
| 길이 · 디코딩 | 메타데이터의 실제 길이가 30초 초과면 길이 오류를 전달한다. 유효한 길이나 프레임이 없거나 해독에 실패하면 재생 실패를 전달한다. |
| 탐색 · 변환 | 최신 시점과 설정에서 작업에 실패하면 조작부 근처에 실패를 표시하고 재시도할 수 있게 한다. 이전 작업의 결과·실패는 현재 상태를 갱신하지 않는다. |
| PNG 인코딩 | PNG 생성에 실패하면 다운로드를 시작하지 않고 같은 설정으로 재시도할 수 있게 한다. |

샘플 자산의 로딩 실패도 입력 화면의 재생 실패로 안내한다. 오류 문구와 버튼 상태는 [화면설계서](화면설계서.md)를 참조한다.

## 4. G2 검토와 후속 변경

- AC-001, AC-002, AC-003, AC-005, AC-006, AC-007에서 로딩·변환·다운로드 동작과 실패 경로를 확인한다.
- AC-008에서는 브라우저 네트워크 기록으로 정적 자산 요청과 로컬 미디어 처리를 확인한다. 로컬 영상, 추출 프레임 또는 PNG가 서버 요청에 포함된 건수는 0이어야 한다.
- 서버에서 미디어나 사용자 데이터를 다루는 기능이 범위에 추가되면 변경 승인 후 데이터 흐름·인증·API 계약을 다시 검토한다.
