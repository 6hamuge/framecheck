## 1. 목적과 범위

같은 영상의 동일 시점과 영역에서 원본과 JPEG 변환본을 비교하고, 최신 결과를 PNG로 저장할 수 있는지 검증한다. SRS의 기능 요구사항 7개와 비기능 요구사항 4개를 대상으로 한다. 서버 API·DB 검증은 브라우저 내부 처리 구조에 따라 해당 없음으로 기록한다. 실습의 독립 완료율과 사용자의 압축 조건 이해도는 기획서 KPI로 별도 판정한다.

## 2. 테스트 전략

| 단계 | 대상·방법 | 담당 역할 |
| --- | --- | --- |
| 단위 검증 | 원본 좌표·대응 경계·최소 1px 및 짝수·홀수 예시를 표 기반으로 검증한다. 코드와 결과를 후보 SHA에 연결한다. | 개발 |
| 브라우저 통합 | 입력·탐색·JPEG·PNG의 실제 브라우저 경로를 확인한다. 테스트용 지연·실패 주입으로 비동기 완료 순서와 변환·저장 실패 시 재시도를 검증한다. | 개발·QA |
| 시스템·인수 | 실제 데스크톱·모바일에서 샘플과 로컬 영상의 전 과정을 실행한다. PNG를 직접 열어 비교하고, 네트워크·저장소·키보드·보조 기술과 화면 전환을 확인한다. 학회 시연 영상에서 작은 얼굴의 눈·입 영역을 비교한다. | QA·실습 담당 |

실패 주입은 검증 환경에서만 사용한다. 실제 JPEG 여부는 인코딩에 전달한 타입·품질과 결과 Blob 및 디코딩된 결과를 확인한다. 같은 픽셀 결과가 나올 수 있으므로 눈에 띄는 차이만으로 통과를 판정하지 않는다.

## 3. 환경과 테스트 자료

- **환경** · 후보는 G4 인계서의 SHA·정적 아티팩트로 식별한다. 작업 폴더 루트에서 `python3 -m http.server 8000 --bind 127.0.0.1 --directory framecheck/dist`로 제공하고 `http://127.0.0.1:8000/`을 연다. 후보와 연결된 HTTPS 미리보기로도 검증할 수 있다.
- **대상 매트릭스** · DEC-002에서 브라우저·OS·기기·지원 코덱 조합을 확정한다. 최소 검증 범위는 합의한 데스크톱·모바일 환경, 샘플·재생 가능한 MP4·WebM, 767px·768px 화면 전환 및 키보드·상태 전달이다.
- **증빙** · 실제 파일 바이트, 브라우저가 읽은 영상 길이와 해상도, 설정, 기대·실제 결과를 함께 기록한다. 저장·네트워크를 입증할 때는 권리 확인된 테스트 파일과 결과를 사용한다.

| 픽스처 | 준비 기준 |
| --- | --- |
| 샘플 | 출처·배포·시연 권리 및 같은 영상에서 추출한 포스터 확인. 얼굴이 작게 나온 장면 포함. DEC-001에서 확정. |
| 정상 로컬 영상 | 현재 브라우저에서 재생 가능한 MP4·WebM. 구분되는 두 시점과 세부가 보이는 프레임 포함. |
| 입력 경계 | 50,000,000·50,000,001바이트 파일은 30초 이하로 준비한다. 30초·30초 초과 파일은 50,000,000바이트 이하로 준비한다. 나머지 조건은 유효하게 유지한다. |
| 입력 오류 | 지원되지 않는 형식, 손상된 MP4 또는 대상 브라우저에서 해독할 수 없는 지원 컨테이너. |
| 픽셀·실패 주입 | 짝수 크기와 홀수 가장자리의 기준 프레임. 최신 결과가 먼저 완료되는 상황과 JPEG·PNG 생성 실패를 각각 재현할 검증 환경. |

미리보기의 100%·JPEG 품질 75 기본값과 픽셀 반올림은 상위 설계의 승인값을 기준으로 판정한다. 승인 전에는 검토안으로 기록한다.

## 4. 진입·종료 기준

| 구분 | 기준 |
| --- | --- |
| G4 진입 | 후보 SHA·아티팩트, QA 담당자와 접근, 코드 검토·사전 점검, 승인 샘플·픽스처 및 대상 브라우저 확보. 범위의 TC-ID를 RTM에 연결하고 알려진 제약을 확인한다. |
| G5 종료 | 대상 후보와 환경에서 계획에 포함한 필수 케이스를 실행하고 SRS의 필수 수용 기준을 충족한다. 미해결 출시 차단 결함을 해소하고 수정 후보에서 재검증한다. 허용 예외가 있다면 영향, 우회 방법, 승인자를 기록한다. 결과보고서와 배포 판단을 G5 승인 기록에 연결한다. |

영상 열기부터 저장까지의 차단, 잘못된 프레임·영역·설정 저장, 사용자 미디어의 서버 전송 또는 영구 앱 저장을 출시 차단 결함 후보로 본다. 전용 성능 수치 목표는 SRS에 정의되지 않았다. 연속 조작의 최신성 및 처리 상태 표시는 AC-007로 검증한다.

## 5. 실행 순서와 보고

1. 개발 담당이 검증 후보와 사전 점검 기록을 인계한다. 콘텐츠 담당과 QA가 픽스처와 대상 환경을 확인한다.
2. QA가 핵심 흐름, 경계·실패, 데이터 처리, 화면·접근성 순으로 검증하고 케이스별 결과와 증빙을 기록한다.
3. 수정 후 실패 케이스와 외부 영향이 있는 핵심 경로를 재실행한다. 결과는 실행한 후보와 환경별로 구분한다.
4. G5에서 승인자, 일시, 검증 범위, 예외 승인 및 배포 판단을 기록한다.

## 6. 얼굴 분석 확장 검증

- 작업실 샘플의 100%·50%에서 두 점 집합과 숫자, 얼굴·눈·입 자동 확대와 기본 PNG를 확인한다.
- 고정 단색 MP4에서 원본 미검출을 검증한다. 샘플의 25%·품질 0에서 대응 얼굴을 찾지 못하는 사례를 확인한다. 미검출을 거짓 수치로 표시하는지 점검한다.
- 다른 파일·시점·압축 설정으로 바꿀 때 이전 결과 제거와 기본 경로를 확인한다. 분석 초기화가 지속되는 중 상태가 바뀐 경우도 재검증한다.
- 초기 CDN·모델 요청을 차단하는 시험과 네트워크 계측을 실시한다. 다운로드 요청의 대상, 프레임·특징점 전송이 없는지, 사용자에게 재시도 경로가 있는지 확인한다. 실제 모바일·스크린리더 범위는 별도로 기록한다.
