## 1. 배포 개요

승인된 `framecheck/dist/` 정적 파일 묶음을 HTTPS 호스트에 올린다. 페이지와 JavaScript·CSS, 샘플 클립 및 포스터는 동일 출처에서 제공한다. 영상 선택 이후의 처리는 브라우저에서 수행한다. DB 마이그레이션, 서버 API 설정 및 사용자 자료 이전은 해당 없음이다.

[테스트결과보고서](../05-테스트/테스트결과보고서.md)는 로컬 후보 15개 케이스 중 13개 통과, 2개 부분 검증으로 기록한다. 2026-11-25 프로젝트 요청자가 실제 모바일 기기 및 스크린리더 검증을 예외로 남기고 소유자 전용 배포를 먼저 진행하도록 승인했다. 접근 범위가 확대될 경우 두 항목을 재검토한다.

## 2. 배포 환경과 준비물

| 환경 | 실행 위치·용도 | 인계 기록 |
| --- | --- | --- |
| 개발·QA 로컬 | 작업 폴더 루트에서 `python3 -m http.server 8000 --bind 127.0.0.1 --directory framecheck/dist`를 실행한다. | 후보 SHA, 브라우저·OS·기기, 테스트 결과 |
| 배포 후보 검증 | 운영과 같은 정적 호스팅 조건에서 현재 후보와 동일한 파일 묶음을 검증한다. | 후보 SHA·아티팩트·검증 주소 및 환경 차이 |
| 학회 시연 | 합의한 HTTPS 주소에서 대상 사용자에게 정적 버전을 제공한다. | 호스트·접근 범위, 배포 ID·URL, 운영 담당 역할 |

릴리스 기록에는 후보 SHA와 변경 범위, 앱·샘플 파일 목록, 테스트 증빙, 샘플의 배포·시연 권리(DEC-001)를 연결한다. 호스트·접근 범위·시연 일시(KST)와 배포·복구 담당자는 G5 이후 배포 실행 전에 확정한다.

## 3. 배포 절차

1. **진입 확인** · G5에서 해당 후보의 검증 종료 기준과 승인된 예외를 확인한다. 배포 담당은 후보 파일과 운영 주소를 대조하고, 이전 검증본 또는 최초 배포의 게시 중단 경로를 확보한다.
2. **정적 배포** · 승인된 파일 묶음을 한 버전으로 게시한다. HTML, JS·CSS, 샘플과 포스터가 같은 릴리스에 속하는지 확인하고, 후보 SHA·배포 ID·일시를 기록한다.
3. **배포 후 점검** · 운영 주소에서 시작 화면, 샘플·포스터 로딩, 대표 데스크톱·모바일의 영상 열기 → 시점 및 영역 선택 → 해상도·품질 변경 → PNG 저장을 확인한다. 권리 확인 테스트 영상과 저장한 PNG를 대조하고, 사용자 미디어가 서버 요청에 포함되지 않는지 확인한다.
4. **G6 인수** · 운영 담당과 함께 릴리스 위치, 점검 증빙, 장애 접수 방법, 복구 위치와 권한을 확인한다. 검토 체크리스트에 배포 버전·확인 일시·담당자 역할과 근거를 남긴다.

## 4. 롤백 계획

운영 페이지 또는 샘플이 열리지 않거나, 승인 환경에서 핵심 흐름이 차단되거나, 잘못된 비교 PNG 또는 사용자 미디어의 외부 전송이 확인되면 운영 담당이 배포 담당과 배포 중단 여부를 판단한다. 권한이 있는 배포 담당이 이전에 검증한 정적 버전 전체를 복원한다. 이전 버전이 없는 첫 배포라면 게시를 중단하고, 문제가 수정된 후보를 G5 기준으로 다시 확인한다. 복구 후 운영 주소에서 시작·비교·저장을 다시 실행하고 복원한 버전, 조치 시각, 재검증 결과를 남긴다.

## 7. 얼굴 분석 확장 배포 체크

검증한 후보에는 `face-analysis.js`를 포함한다. 소유자 검증 환경에서 CDN·모델 HTTPS 다운로드와 WASM 초기화, 샘플 분석, 미검출 및 수동 PNG 경로를 점검한다. 상기 Sites v1 커밋과 예외 승인은 기존 릴리스에 해당한다. 확장 배포 버전·SHA와 신규 확인 결과를 준비하며, 장애 발생 시 기존 Sites v1을 복구 대상으로 사용한다.
