## 1. 목적과 검토 방법

학회 실습 참여자와 영상 편집자가 시작 버튼을 찾고, 같은 시점·영역에서 두 설정의 효과를 구분하고, 결과를 저장할 수 있는지 확인한다. 현재 검토 근거는 설계 문서다. 아래의 설계 반영 여부는 화면 구현이나 사용성 통과 판정을 뜻하지 않는다.

## 2. 휴리스틱 검토

| 관점 | 설계에 반영한 내용 | 구현 후 확인할 사항 |
| --- | --- | --- |
| 시스템 상태 가시성 | 영상 열기·탐색·변환·저장 중 상태 | 빠르게 조작해도 대기 상태와 저장 가능 여부가 일치하는가 |
| 사용자 용어 | 원본, 해상도, JPEG 품질, 실제 픽셀 크기 | 파일·영역 조건과 결과 수치를 처음 읽는 사람이 설명할 수 있는가 |
| 사용자 제어 | 샘플·로컬 전환, 영역 재지정, 오류 후 재시도 | 시점 이동으로 영역을 다시 골라야 함을 알아차리는가 |
| 일관성 | 같은 카드 구조, 시점과 영역 표기 공유 | 화면과 저장 PNG에서 같은 값·용어를 쓰는가 |
| 오류 예방 | 입력 한도, 영역 유효성, 준비 전 저장 잠금 | 상태에 맞는 메시지가 저장 버튼이나 입력 가까이 있는가 |
| 기억 부담 | 버튼 가까이 형식·한도, 각 설정의 현재 값 | 사용자가 한도를 기억하거나 다른 화면에서 확인할 필요가 없는가 |
| 유연한 조작 | 포인터·터치·좌표 입력, 키보드 타임라인 | 세 입력 경로에서 같은 영역을 얻는가 |
| 정보 밀도 | 샘플·시작 버튼, 작업 화면의 동일 비중 비교 카드 | 작은 화면에서 필수 조작이 보이고 픽셀 비교가 어려워지지 않는가 |
| 오류 회복 | 형식·용량·길이·재생 실패를 구분하고 다음 동작을 표시 | 오류 후 다른 영상 또는 샘플로 바로 진행하는가 |
| 도움말 | 영역 드래그 안내, 로컬 처리와 입력 제약 안내 | 수치 입력 단위 및 PNG 저장 조건을 조작부에서 이해하는가 |

## 3. 흐름·반응형·접근성 검증

| 검토 항목 | 절차와 기대 결과 | 추적 |
| --- | --- | --- |
| 첫 화면과 전체 흐름 | 처음 쓰는 참여자가 샘플과 로컬 영상에서 시작, 프레임 이동, 영역 지정, 설정, PNG 저장을 완료한다. | AC-001, AC-002, AC-003, AC-006 |
| 비교의 이해 | 한 설정씩 바꾸고 양쪽의 시점·영역·픽셀 수를 설명한다. JPEG 품질은 같은 해상도에서 크기를 유지한다. | AC-004, AC-005 |
| 반응형 | 767px와 768px 경계에서 세로·가로 배치를 확인한다. 주요 조작에 가로 스크롤이 필요 없어야 한다. | AC-010 |
| 키보드·보조 기술 | 영상 열기, 타임라인, 영역 수치 입력, 두 설정, 저장을 키보드로 진행한다. 레이블·포커스, 로딩·오류 알림, 44px 터치 높이를 확인한다. | AC-011 |
| 처리 상태와 오류 | 지원 범위 밖 파일, 늦게 완료된 이전 작업, JPEG·PNG 실패 후 현재 상태와 복구 동작을 확인한다. | AC-001, AC-007 |

## 4. 결과와 후속 검토

- 문서에서 원본·변환의 공통 시점, 상태 메시지, 키보드 대체 경로와 반응형 기준을 확인했다.
- 실제 후보가 준비되면 **시점 이동 직후 영역 미선택 안내**, **모바일의 비교·저장 동선**, **보조 기술의 로딩·오류 전달**을 우선 확인한다. 통과 여부와 스크린샷은 해당 후보·브라우저에 연결한다.
- 사용성 실습은 서비스 기획서 KPI의 모집과 판정 기준을 적용한다. 완료 여부와 막힌 단계만 기록하고, 사용자의 원본 프레임은 실습 관찰 기록에 포함하지 않는다.

## 5. 얼굴 분석 UX 검토

정상 샘플에서는 모델 요청 후 두 패널의 눈·입 표식, 영역 버튼과 px/% 표기를 확인한다. 점은 눈·입 모양으로 구분하고 텍스트로 위치 차이를 읽을 수 있다. 원본·변환본 미검출 문구와 설정 변경 직후 결과 제거를 검토한다. 데스크톱에서 모델 실패 이후 수동 영역과 PNG 저장을 확인했다. 독립 스크린리더에서의 알림 전달은 추가 검토 대상으로 둔다.
