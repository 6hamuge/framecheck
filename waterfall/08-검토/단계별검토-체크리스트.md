## 공통 승인 기록

단계별 승인 시 기준 문서·빌드, 판정, 승인자, 일시(KST), 확인 근거를 남긴다. 조건부 승인에는 조건·담당·기한과 재확인 근거를 연결한다. 체크 여부는 공식 검토 시 기록한다.

| 게이트 | 현재 상태 | 확인 근거 또는 남은 조건 |
| --- | --- | --- |
| G0 | 미검토 | 기획·정책 초안. 샘플 권리, 대상 환경과 실습 목표 확인 필요. |
| G1 | 미검토 | SRS 11개 요구사항, 유스케이스 5개, RTM 초기 연결 초안. |
| G2 | 미검토 | 아키텍처·API·DB·화면 설계 초안. 기본 설정·픽셀 계산 규칙 검토안. |
| G3 | 미검토 | 상세설계 모듈과 수용 기준 연결 초안. 상위 기준선과 개발 준비 확인 필요. |
| G4 | 진입 조건 미충족 | 작업 폴더에서 실행 가능한 후보 미확인. QA 인수·증빙 대기. |
| G5 | 판정 대기 | 테스트 15개 정의, 0개 실행. |
| G6 | 운영 인수 대기 | 배포 버전·URL·담당자 및 배포 후 증빙 미확정. |

## Phase 0 기획 검토

- [ ] [서비스기획서](../00-기획/서비스기획서.md)의 사용자 문제 가설, MVP 6개 및 제외 범위, 실습 성공 지표를 확인했다.
- [ ] [비즈니스정책서](../00-기획/비즈니스정책서.md)의 입력 제한, 브라우저 처리, 비교·저장 규칙과 샘플·환경 결정 상태를 확인했다.

## Phase 1 요구사항 검토

- [ ] [SRS](../01-요구사항분석/요구사항명세서-SRS.md)의 11개 요구사항에 테스트 가능한 수용 기준이 있다.
- [ ] [유스케이스](../01-요구사항분석/유스케이스명세서.md)의 정상·대안·예외 흐름과 [RTM](../01-요구사항분석/요구사항추적매트릭스-RTM.md)의 MVP·정책 연결을 확인했다.

## Phase 2 시스템 설계 검토

- [ ] [SAD](../02-시스템설계/시스템아키텍처설계서-SAD.md)의 정적 배포와 브라우저 처리 경계, 최신 결과 및 픽셀 규칙을 승인했다.
- [ ] [API](../02-시스템설계/API설계서.md)와 [DB](../02-시스템설계/데이터베이스설계서.md)의 비적용 사유와 브라우저 계약을 확인했다.
- [ ] [화면설계서](../02-시스템설계/화면설계서.md)의 초기 설정, 반응형·접근성, PNG와 오류 상태를 검토하고 요구사항과 연결했다.

## Phase 3 상세 설계 검토

- [ ] [상세설계서](../03-상세설계/상세설계서.md)의 모듈 책임, 상태 전이, 프레임 직렬화와 늦은 결과 폐기, 임시 URL 정리를 검토했다.
- [ ] 압축·영역 결정, 모듈·수용 기준 연결, 코딩 규칙 및 개발 환경을 확인했다.

## Phase 4 구현 검토

### 4.5 G4 테스트 인계

- [ ] [구현·테스트 인계서](../04-구현/구현-테스트-인계서.md)에 후보 SHA·아티팩트, 실행 환경·접근과 검증 자료가 있다.
- [ ] 코드 리뷰·사전 점검과 남은 제약에 증빙·담당자를 연결했다.
- [ ] 테스트 대상 TC-ID를 RTM에 연결하고 QA가 환경과 픽스처를 확인했다.

## Phase 5 테스트 검토

- [ ] [테스트계획서](../05-테스트/테스트계획서.md)의 대상 환경과 종료 기준을 확인했다.
- [ ] [테스트케이스](../05-테스트/테스트케이스.md)와 [테스트결과보고서](../05-테스트/테스트결과보고서.md)의 후보별 실행 결과와 PNG·접근성·브라우저 데이터 경계 증빙을 확인했다.
- [ ] 출시 차단 결함의 수정·재검증, 승인 예외, 배포 판단과 근거를 기록했다.

- [ ] 배포 후 샘플·로컬 입력에서 화면과 PNG가 정상이며 사용자 미디어 처리 경계를 확인했다.
